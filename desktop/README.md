# kinora Desktop

本地桌面客户端，Windows / macOS / Linux，基于 [Tauri 2](https://tauri.app)。界面是本地渲染器（`src/renderer/`），使用**操作系统自带的 WebView**（Windows WebView2、macOS WKWebView、Linux WebKitGTK），不打包浏览器内核，因此安装包只有几 MB（Linux `.deb` 约 1.9 MB；Electron 版约 100 MB）。数据经 Rust 主进程的受限桥接从云端 API 读取。计算和任务持久化仍在云端；关闭客户端不会取消任务。

- **动作库**：一个搜索框同时支持动作编号（完整、前缀或片段）和描述模糊搜索，中文可匹配英文提示词（`/api/library/find`，见 `docs/INDEXING.md`）；可按最相关、时长、制作时间排序，分页显示全部相关动作。云端未更新时自动退回旧的英文关键词检索（不支持排序）。主题/审核状态/“我的”筛选、骨架缩略图、可拖动旋转的三维预览（左/右侧分色、根轨迹、时间轴、0.25–2× 速度、循环）。检查面板展示人工审核、TMR 机器评分和源动作质量；未知项显示为未评分/未知。
- **生成**：服务器改写或英文原文直传（`exact_english`），本地实时检查格式（A person 开头、12–70 词、时长随云端模型动态校验（当前 Kimodo 为 1–120 秒））。任务以卡片流展示进度、队列位置、英文提示词与结果；超时后重提相同内容复用请求编号，失败任务以新任务重试并保留父任务链接。
- **重定向**：必须明确选择目标机器人；可选直接参数 JSON。完成后在 three.js 中播放机器人实体预览，并通过本机保存对话框下载 NPZ。
- **账号**：登录页提供申请账号与忘记密码入口，在服务器网页完成邮箱验证和重置；验证后直接开通普通账号，支持邮箱或用户名登录。
- **设置**：账户、修改密码、邮箱账号入口、服务器地址配置与重新连接、清除本机登录，以及签名更新检查、下载和重启安装。审核、生产、存储、管理等功能通过“网页工作台”在独立临时沙箱窗口打开（无 IPC 权限，需在该窗口单独登录）。

桌面端使用现有云端账号直接下载人体源动作，不需要 Gadget API Key。动作库预览区可下载单个动作或打开批量面板；编辑页“我的拼接与修正结果”集中展示最近 100 个任务中的候选，支持预览和下载。NPZ 保留人体源数据；BVH 导出 SMPL-H 骨架动画（厘米、Y 轴向上、ZXY 旋转通道），不改变 root 轨迹，也不包含机器人重定向。多选最多 20 个动作，下载 ZIP，包内 export-report.json 逐项记录成功和失败；批次未压缩数据总量限制 64 MiB。

## 系统要求

- **Windows 10/11**：需要 WebView2（Windows 11 与已更新的 Windows 10 已自带；缺失时安装程序会联网安装）。
- **macOS 11+**：一个通用安装包同时支持 Apple 芯片和 Intel。
- **Linux**：`.deb`，依赖系统的 `libwebkit2gtk-4.1-0`（Ubuntu 22.04+、Debian 12+）。

各平台 WebView 版本不同，渲染细节可能略有差异；三维预览需要 WebGL。

## 安全边界

- 渲染器是本地页面，CSP 只允许连接 Tauri IPC，不能直接访问网络；只能经 `window.desktop.cloud()`（`src/renderer/bridge.js`）请求。
- Rust 端 `src-tauri/src/policy.rs` 以“方法 + 路径”白名单限定可访问端点（检索、预览、生成/重定向提交与取消、登录相关），查询参数仅允许标量值；生产控制、用户管理、存储等管理接口不在白名单内。拒绝重定向，只允许 HTTPS。
- TLS 使用操作系统证书库（Windows SChannel / macOS 钥匙串 / Linux OpenSSL），从不跳过校验；私有 CA 需安装到系统受信任根证书。
- 登录 Cookie `mf_session` 只保存在 Rust 端，持久化到应用数据目录的 `session.json`（Unix 权限 0600），不暴露给渲染器。写请求附加服务器要求的 `Origin` 与 `X-MotionFarm-Request` 头。
- 下载仅允许重定向结果与授权人体动作导出，校验当前登录账号和动作访问权限；文件名会被清理，先写入 `.part` 再重命名。
- IPC 权限（`src-tauri/capabilities/default.json`）只授予主窗口；网页工作台窗口加载远程页面，没有 IPC 权限，且不能离开 kinora 源。

## 开发

需要 Node.js 22+、Rust stable，以及平台依赖（Linux：`libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev libssl-dev`；见 [Tauri 前置条件](https://tauri.app/start/prerequisites/)）。在 `desktop/` 执行：

```sh
npm ci
npm test          # cargo test：端点白名单与登录 Cookie
npm run dev       # 开发运行
npm run build     # 生成本机平台安装包
```

产物在 `src-tauri/target/release/bundle/`（macOS 通用包在 `src-tauri/target/universal-apple-darwin/release/bundle/`）。

`npm run dev` 使用独立的 `kinora Dev` 标识 `com.motionfarm.desktop.dev`，与正式版分开保存服务器配置、会话和系统凭据。测试版不从正式更新源升级；重新构建测试安装包即可更新。正式构建仍使用 `com.motionfarm.desktop`，兼容已有安装。

同一操作系统用户会话内，相同应用标识只运行一个实例；重复打开会恢复并聚焦已有主窗口。macOS 使用进程持有的文件锁和本地通知，进程崩溃后锁自动释放；Windows/Linux 使用 Tauri 单实例插件。多客户端测试应给每个客户端分配不同的标识，例如 `com.motionfarm.desktop.test-a`、`test-b`、`test-c`。旧版未实现单实例保护，需要先退出。

新电脑首次启动先显示“连接服务器”，保存地址前不向默认服务器发送请求。可输入 `localhost:8765`、`127.0.0.1:8765` 或 `https://kinora.example.com`；端口应替换为实际服务端口。省略协议时，本机回环地址使用 HTTP，其他地址使用 HTTPS。只有回环地址允许 HTTP；远程证书必须通过系统信任验证。地址只接受根地址，不接受其中夹带的账号密码、路径、查询参数或片段。

配置后仍使用服务器上的用户名和密码登录，不增加接入密钥。设置中可随时更改服务器；保存后刷新客户端界面，丢弃旧服务器的预览与编辑缓存。登录凭据和原生会话按完整服务器地址隔离，排队中的旧服务器请求会被拒绝。已保存的服务器地址继续使用；没有保存地址或配置损坏时需手动填写。连接失败时仍可从设置更改地址或重新连接。

应用从公开 Kinora GitHub Releases 检查签名更新；检查更新不携带业务服务器的登录凭据，安装包继续由内置公钥验证。检查、下载或安装更新期间暂不允许切换服务器。

## 云端自动打包

推送到任意分支且改动了 `desktop/` 时，GitHub Actions 工作流 `Desktop installers`（`.github/workflows/desktop-build.yml`）会在原生 Windows / macOS / Linux 机器上构建安装包，也可在 Actions 页面手动运行。完成后在该次运行页面底部 Artifacts 下载 `kinora-0.4.12-windows-x86_64`（`.exe`）、`kinora-0.4.12-macos-universal`（通用 `.dmg`）、`kinora-0.4.12-ubuntu-x86_64`（`.deb`），保留 14 天。不会创建 Release，也不会上传到仓库。

这些安装包**未签名**：Windows 会出现 SmartScreen 提示（“更多信息 → 仍要运行”）；macOS 只有 ad-hoc 签名、未公证，首次需右键“打开”，遇到签名或完整性错误时应停止安装并检查构建来源与签名。以明确标注的测试版分发；自动更新由 Tauri 独立签名，沿用原公钥校验。

## 应用更新与正式发布

正式桌面发布从当前分支的 Desktop installers 构建取用签名候选包。三平台构建和原生验收通过后，工作流摘要提供候选 ZIP 的 Actions artifact ID 与 SHA-256。用[公开 Kinora 发布流程](https://github.com/PoirotJin/kinora/blob/main/docs/PUBLISHING.md)进行解包检查和正式发布。签名更新由 GitHub 提供，业务服务器不需要部署桌面更新文件。

此前安装的客户端可以用新的安装包覆盖安装，以切换至 GitHub 更新地址。更新签名不替代 Apple 公证或 Windows 代码签名。

## 每版更新说明

每个新版本首次启动显示随安装包内置的更新说明，点击“知道了”后记住已读状态。首次服务器配置优先显示。设置中的“查看本次更新”可随时重新打开，关闭说明或按 Escape 后仍保留设置窗口；清除登录不会清除已读状态。发布时必须同步更新 `src-tauri/release-notes.json`，构建会检查版本一致且说明非空。

## 验证范围

`npm test`（`cargo test`）覆盖服务器地址解析、首次配置、旧安装迁移、跨服务器会话隔离、过期请求拒绝、设置/版本说明返回行为、导航策略、API/下载白名单、文件名清理，以及登录 Cookie 的解析、持久化与清除。

验证记录应按版本和平台分别保存。此前已在本机 macOS 验证正式 `.app` 启动与真实云端动作流程；这不代表 Windows、Linux 或其他架构完成真机验收。

## 在线编辑修正

主导航“编辑修正”复用网页工作台的修正服务，支持载入动作库选中项、指定起止帧、提交描述、刷新云端任务、原动作与候选对比以及接受新版本。使用现有 kinora 配色、表单和骨架渲染器。任务在云端保留，原动作不覆盖。后端需开启 editing_enabled；英文可直传，中文请选择已配置的改写模型。进度通过“刷新任务”并打开任务更新。

### 0.4.8 图形化选区

编辑页提供骨架缩略帧时间轴。拖动空白轨道划选、两端裁剪、选区整体移动；点击刻度或拖动播放头定位。支持 1–16 倍缩放、适合窗口、I/O 标记入点出点、方向键逐帧微调（Shift 为 10 帧）、Escape 撤销当前拖动。结束帧不包含在选区内；12–300 帧之外标红并阻止提交。精确帧数输入折叠保留。

### 开发中：剪辑式编辑布局（拼接第 1–2 阶段）

编辑页改为剪辑软件布局：左上为素材箱与检查器（另有“片段修正”标签保留原修正流程），右上为监视器，底部为时间线。

- 素材箱：按编号或动作库选中项导入，拖到时间线或点击“加入”。时间线最多两段，中间自动留出过渡。
- 整段变换：每段绕首帧根节点在地面（Y 轴向上，X/Z 平面）旋转并平移，只改根位置和朝向，不改身体姿态。监视器“俯视”中拖动轨迹平移、拖动圆形手柄旋转（Shift 吸附 15°），macOS 触控板双指旋转，Shift+滚轮旋转，方向键/方括号微调；检查器可输入精确数值。
- 时间线：拖动片段两端裁剪（裁剪入点时自动补偿，轨迹不跳动），点击刻度定位，空格播放。
- 过渡：按两段间距和转向自动建议 1–4 秒，可手动改；超过自然步行速度（1.6 米/秒）或转向过急（120°/秒）时标红。监视器里的过渡是占位插值。
- Kimodo 拼接（`POST /api/harness/splice`，云端 `splicing_enabled` 时可用）：云端按相同约定裁剪并刚体变换两段，拼成“A + 占位过渡 + B”的新中间动作，再把过渡区间交给已验证的 Kimodo 局部修复重新生成（自然踏步提示词；A 尾部与 B 首部全身约束；选区外逐位不变；沿用边界位置/速度/加速度与转角门槛）。完成后自动在监视器中播放（优先显示通过接缝检查的候选；提交后改过时间线则只加载、不切换画面），监视器上方可在“时间线序列”与“Kimodo 结果”之间切换，也可加入素材箱或接受。原动作始终不变，失败的候选隔离保存。服务端见 `g2h/motion_splice.py`。

提交前的变换只在本地预览，不修改任何云端动作。模型与几何计算见 `src/renderer/sequence.js`，测试见 `tests/sequence.cjs`。

### 自定义机器人模型（0.4.14）

重定向页 →“目标机器人”标题右侧的“自定义机器人”。支持 MJCF XML、URDF，以及包含模型和资源目录的 ZIP；32 MB 上传、128 MB 解压、2000 文件，每个账号最多 20 个模型。模型包内的相对路径与 MJCF include 会检查资源是否完整。多个入口可手动选择。

模型按登录账号隔离保存，原始包不修改。预览展示实际 MuJoCo 编译后的几何和基础颜色，以及关节限位；暂不展示纹理贴图。导入模型尚不能直接提交重定向，必须完成独立的人体关节映射、碰撞对与求解配置后再启用；不会套用内置机器人的参数。

### 0.4.16 界面整理与播放

- 新功能（编辑修正、下载对话框、自定义机器人）统一为原有的纸色、细线、直角和文字按钮风格；导航顺序为动作库、生成、重定向、编辑修正（Ctrl+1–4）。

### 0.5.0 实体机器人精修

精修使用任务实际机器人模型，关节滑块实时更新实体姿态，支持视角旋转/缩放、部位与关节轴高亮、原轨迹叠加和关键帧草稿播放。部位目标仍需服务端求解；草稿不代表验收通过。候选增加全轨迹编辑增量的速度、加速度与突变检查，继续执行碰撞、限位和动力学验收，通过后须明确接受才能导出。

版本规则见 [VERSIONING](../docs/VERSIONING.md)，操作及验收范围见 [ROBOT_EDITOR_3D](../docs/ROBOT_EDITOR_3D.md)。发布须更新 GitHub 安装包、官方下载入口和签名更新清单。macOS 同一通用包支持 Apple silicon / Intel；Windows 与 Linux 支持 x86_64。沿用现有应用标识、更新公钥和用户设置。

登录后从主导航进入 Gadget 接入，创建、查看或撤销当前用户的个人密钥；默认只读，可选生成和导入/重定向权限。完整密钥仅本次显示，离开页面、退出登录或切换服务器时清除。客户端下载当前服务器的 Gadget 包，并根据本机绝对路径生成不含密钥的 JSON/TOML 配置。密钥通过仅本人可读的文本文件提供，无需登录管理员网页。服务器继续校验所有权、有效期与权限；Gadget 软件包版本不变。
